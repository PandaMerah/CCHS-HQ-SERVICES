⚡ Dual-Layer Persistence Active (Firebase RTDB + Server JSON)
Every room and booking change writes directly to Firebase (/rooms and /bookings) and persists to the HQ Server database (CCHSMeetingDashboard/data.json via /api/data)—not just browser localStorage.
If your Firebase Console Realtime Database Rules are currently locked (401 Permission Denied), paste these rules in Firebase Console → Realtime Database → Rules (or run npx firebase-tools deploy --only database): 
{
  "rules": {
    "rooms": { ".read": true, ".write": true },
    "bookings": { ".read": true, ".write": true },
    "config": { ".read": true, ".write": true },
    "departments": { ".read": true, ".write": true },
    "history": { ".read": true, ".write": true },
    "remoteDisplay": { ".read": true, ".write": true }
  }
}
